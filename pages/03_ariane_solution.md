# פתרון: 3. אריאן 5, יוני 1996

<p><a href="../board.html?round=ariane">→ חזרה ללוח התשובות</a></p>

**התשובה: -25,536.** הערך של Ariane 5 לא נכנס לטווח, ובספירה במעגל הוא הופך למספר שלילי.

## הנתונים

הפרמטרים מתא הנתונים בעמוד, שעליהם מבוססות כל השורות בהמשך:

```python
ariane4_max = 20000.3      # the largest value reached on Ariane 4 trajectories
ariane5 = 40000.7          # the value reached on the first Ariane 5 flight
```

## שלב אחר שלב

הסעיפים כאן זהים לסעיפי העמוד. סעיפים 1 ו-2 עוסקים ביכולת של הרגיסטר, סעיף 3 בשני הערכים, וסעיפים 4 ו-5 בערך שנשמר.

**1. כמה ערכים יש ב-16 ביט.** לכל ביט שני מצבים:

```python
n_values = 2**16                # 65,536
```

**2. הטווח של מספר חתום.** מחצית מהצירופים שמורים למספרים שליליים, והאפס תופס מקום אחד מהחיוביים:

```python
smallest = -2**15               # -32,768
largest = 2**15 - 1             # 32,767
```

**3. המרה לשלם ובדיקת טווח.** `int` חותך את מה שאחרי הנקודה ואינו מעגל:

```python
n4 = int(ariane4_max)           # 20000
n5 = int(ariane5)               # 40000 (int truncates the .7)
smallest <= n4 <= largest       # True
smallest <= n5 <= largest       # False
```

**4. הנוסחה על הערך של Ariane 4.** בתוך הטווח הספירה במעגל לא משנה דבר:

```python
(n4 + 2**15) % 2**16 - 2**15    # 20000
```

**5. הערך שנשמר עבור Ariane 5.** זו התשובה שמגישים:

```python
stored = (n5 + 2**15) % 2**16 - 2**15    # -25536
```

## מה השתבש

התוכנה נכתבה ל-Ariane 4, שבמסלולים שלה הערך לא התקרב לגבול, ולכן ויתרו על בדיקת טווח. ל-Ariane 5 היה מסלול שונה עם מהירות אופקית גדולה יותר, והערך חרג מהטווח כבר בשניות הראשונות של הטיסה.

## תשובות שגויות נפוצות

- **40,000:** הערך לפני השמירה, בלי הספירה במעגל (סעיף 5).
- **40,001:** הנחה ש-`int` מעגל. הוא חותך (סעיף 3).

## למי שסיים

הערך הקטן ביותר שכבר לא נכנס הוא 32,768, והוא הופך ל--32,768: מהערך החיובי הגדול ביותר קופצים לשלילי הגדול ביותר. מחשב שמחשב לפי ערך כזה מקבל כיוון הפוך לגמרי.
